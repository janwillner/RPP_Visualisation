# The documentation page is the PLC library guide

ADR 0012 made `/docs` an API documentation for programs that read the gateway: the WebSocket messages, `/health`, the
recording files, server options, then the PLC contract and the library guide. The people who open it from the web app's
status bar are PLC programmers, who connect a machine with the library `Syn_Visu`. For them the page started with
what they do not need, and the method reference lived in the contract, a document for the maintainers of the
library and the gateway.

So `/docs` now shows only the library guide (`docs/plc-library-guide.md`), with diagrams and the reference of every
object, method and enumeration of the library at its end. The diagrams are SVG files in `docs/images/`, linked from
the guide as images so that they also show on GitHub. The gateway inlines them into the page, with ids prefixed by
the file name so that the arrow markers of two diagrams do not clash, and the package bundle embeds them with the
guide. Each SVG brings its own colours for light and dark mode, chosen like the web app's palette.

`/docs/schema.json` stays: the JSON Schema of the messages, the health report and the recording file lines, with a
description of every field. `docs/api.md` stays in the repository for programmers of clients and points to it. The
generated reference, its simulator examples and the server options are no longer on the page; `--help` lists the
options.

## Considered Options

- **Keep one page for both audiences, the guide first.** PLC programmers would still scroll past the message
  reference, and every change to the page would have to serve two readers.
- **Draw the diagrams in the page (inline SVG in the Markdown, or generated by the gateway).** The Markdown would no
  longer read well on GitHub, and diagrams in code are harder to change than a drawing.
- **Serve the SVGs as files next to the page.** The page would no longer be one self-contained answer, and the
  diagrams could not follow the page's colour scheme as inline SVG does.

## Consequences

- A diagram the guide links but `docs/images` lacks fails the tests; so does a link to an anchor that is not on the
  page.
- The library's method reference moved from `docs/plc-contract.md` to the guide; the contract keeps the structures,
  naming rules, conventions and the protocol history.
- Programs reading the gateway find no human-readable reference on the server any more, only the JSON Schema with
  its descriptions.
